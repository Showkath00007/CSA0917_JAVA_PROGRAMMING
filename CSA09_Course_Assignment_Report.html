1. PROBLEM STATEMENT & BACKGROUND CONTEXT

SwiftBook Live operates seat-booking systems for high-demand concert halls, performing arts centres, and sports arenas. On major event days, dozens of box-office counter terminals and online portals concurrently attempt to book seats for the same venue at the exact same instant. In legacy paper-based or naive unsynchronized software, this high volume of simultaneous requests produces a severe concurrency bug: multiple counter clerks successfully sell the same physical seat to different customers.

This is a classic concurrency race condition: multiple independent threads of execution (representing counter staff or online buyers) compete for a shared, limited resource (the venue seat inventory) without an atomic coordination mechanism. Because the check for availability and the reservation mutation occur as separate operations, thread interleaving allows both threads to read the status as AVAILABLE before either can record it as BOOKED. Both agents report success to their respective buyers, creating double-booking defects that cause severe operational disruption, financial penalties, and customer distress.

As a software engineer in SwiftBook's Java Core Systems Team, my assignment is to design, implement, and rigorously validate an enterprise-grade desktop booking application that permanently eliminates the double-booking anomaly while remaining lightweight enough to run reliably on counter machines.

Key System Goals:

  • Polymorphic Domain Modeling: Model diverse event types and pricing tiers using OOP principles.
  • High-Performance Inventory: Maintain seat collections using O(1) hash maps, synchronized ledgers, and sorted iterators.
  • Defensive Exception Architecture: Trap out-of-range requests and raise user-defined checked exceptions on contention.
  • Relational Persistence: Save all bookings to an embedded SQLite database using JDBC.
  • Visual Dashboard: Provide an interactive AWT GUI with real-time audit logging.
  • Concurrency Verification: Empirically demonstrate the race condition bug without synchronization and prove complete safety once synchronization is applied.

6. ALGORITHM & PSEUDOCODE FOR THE BOOKING WORKFLOW

The booking algorithm enforces defensive bounds validation, monitor synchronization, custom exception raising, and real-time GUI refreshing.

BEGIN bookSeat(seatNumber, customerName)
 1. INPUT: seatNumber (Integer), customerName (String)
 2. VALIDATION PHASE:
    TRY
       IF seatNumber < 1 OR seatNumber > totalSeats THEN
          THROW ArrayIndexOutOfBoundsException("Seat number out of range")
       END IF

 3. ATOMIC SYNCHRONIZED EXECUTION PHASE:
       ENTER synchronized(this) // Acquire monitor lock on inventory
          seatObj <- seatMap.get(seatNumber)
          
          IF seatObj.status == SeatStatus.BOOKED THEN
             THROW SeatAlreadyBookedException("Seat " + seatNumber + " is already booked.")
          ELSE
             seatObj.status <- SeatStatus.BOOKED
             bookingHistory.add(customerName + " booked seat " + seatNumber)
             bookingDAO.insertBooking(eventId, seatNumber, customerName)
             LOG "Seat successfully allocated"
          END IF
       EXIT synchronized // Release monitor lock

 4. EXCEPTION HANDLING & RECOVERY PHASE:
    CATCH ArrayIndexOutOfBoundsException e
       DISPLAY_ALERT "Invalid seat selected."
    CATCH SeatAlreadyBookedException e
       DISPLAY_ALERT "Failed: " + e.getMessage()
    FINALLY
       refreshGuiSeatGrid()
       flushTransactionLogs()
    END TRY
END

By enclosing the state check and state mutation within the synchronized critical section, race conditions between competing threads are completely eliminated.

package com.swiftbook.booking.model;

public class ConcertEvent extends Event {
    private final String artist;
    private static final double VIP_SURCHARGE = 0.40; // 40%

    public ConcertEvent(String eventId, String name, double basePrice, String artist) {
        super(eventId, name, basePrice);
        this.artist = artist;

    public double computeFinalPrice(String seatCategory) {
        double price = getBaseTicketPrice();
        if ("VIP".equalsIgnoreCase(seatCategory)) {
            price += price * VIP_SURCHARGE;
        }
        return price;
    }

    public String getArtist() { return artist; }
}

model/SeatInventory.java (Part 1: State & bookSeat)
package com.swiftbook.booking.model;

import java.util.*;
import com.swiftbook.booking.exception.SeatAlreadyBookedException;

public class SeatInventory {
    private final Map<Integer, Seat> seatMap = new HashMap<>();
    private final List<String> bookingHistory =
            Collections.synchronizedList(new ArrayList<>());

    public SeatInventory(int totalSeats, String category) {
        for (int i = 1; i <= totalSeats; i++) {
            seatMap.put(i, new Seat(i, category));
        }
    }

    private Seat getSeat(int seatNumber) {
        if (!seatMap.containsKey(seatNumber)) {
            throw new ArrayIndexOutOfBoundsException(
                    "Seat number " + seatNumber + " is out of range.");
        }
        return seatMap.get(seatNumber);
    }

    // synchronized: prevents two threads from booking the same seat at once
    public synchronized void bookSeat(int seatNumber, String customerName)
            throws SeatAlreadyBookedException {
        Seat seat = getSeat(seatNumber);
        if (seat.getStatus() == SeatStatus.BOOKED) {
            throw new SeatAlreadyBookedException(
                    "Seat " + seatNumber + " is already booked.");
        }
        seat.setStatus(SeatStatus.BOOKED);
        bookingHistory.add(customerName + " booked seat " + seatNumber);
    }

10. SOURCE CODE – INVENTORY ENGINE (PART 2)

model/SeatInventory.java (Part 2: cancelSeat & getAvailableSeats)
    public synchronized void cancelSeat(int seatNumber) {
        getSeat(seatNumber).setStatus(SeatStatus.AVAILABLE);
        bookingHistory.add("Seat " + seatNumber + " cancelled");
    }

    // Generics + Iterator usage while searching for available seats
    public Set<Integer> getAvailableSeats() {
        Set<Integer> available = new TreeSet<>();
        Iterator<Map.Entry<Integer, Seat>> it = seatMap.entrySet().iterator();
        while (it.hasNext()) {
            Map.Entry<Integer, Seat> entry = it.next();
            if (entry.getValue().getStatus() == SeatStatus.AVAILABLE) {
                available.add(entry.getKey());
            }
        }
        return available;
    }

    public List<String> getBookingHistory() { return bookingHistory; }
}

Technical Analysis of Data Structures

  • HashMap<Integer, Seat>: Enables O(1) average-time complexity on lookups by seat number. Because booking verification is the most frequent operation, this delivers superior throughput compared to linear list searches.
  • Collections.synchronizedList: Wraps an ArrayList in a synchronized proxy to preserve chronological audit records across asynchronous threads.
  • TreeSet<Integer> & Iterator: Implements the standard Iterator design pattern to safely traverse map entries and return naturally sorted seat numbers to the GUI.

package com.swiftbook.booking.dao;

import java.sql.*;

public class BookingDAO {
    private static final String URL = "jdbc:sqlite:swiftbook.db";

    private Connection getConnection() throws SQLException {
        return DriverManager.getConnection(URL);
    }

    public void createTable() throws SQLException {
        String sql = "CREATE TABLE IF NOT EXISTS bookings (" +
                "booking_id INTEGER PRIMARY KEY AUTOINCREMENT, " +
                "event_id TEXT NOT NULL, seat_number INTEGER NOT NULL, " +
                "customer_name TEXT NOT NULL, status TEXT NOT NULL)";
        try (Connection con = getConnection(); Statement st = con.createStatement()) {
            st.execute(sql);
        }
    }

    public void insertBooking(String eventId, int seatNumber, String customer)
            throws SQLException {
        String sql = "INSERT INTO bookings (event_id, seat_number, " +
                "customer_name, status) VALUES (?, ?, ?, 'BOOKED')";
        try (Connection con = getConnection();
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, eventId);
            ps.setInt(2, seatNumber);
            ps.setString(3, customer);
            ps.executeUpdate();
        }
    }

    public void updateBookingStatus(int seatNumber, String status) throws SQLException {
        String sql = "UPDATE bookings SET status = ? WHERE seat_number = ?";
        try (Connection con = getConnection();
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setString(1, status);
            ps.setInt(2, seatNumber);
            ps.executeUpdate();
        }
    }

    public void deleteBooking(int seatNumber) throws SQLException {
        String sql = "DELETE FROM bookings WHERE seat_number = ?";
        try (Connection con = getConnection();
             PreparedStatement ps = con.prepareStatement(sql)) {
            ps.setInt(1, seatNumber);
            ps.executeUpdate();
        }
    }
}

package com.swiftbook.booking.concurrency;

import com.swiftbook.booking.model.SeatInventory;
import com.swiftbook.booking.exception.SeatAlreadyBookedException;

public class BookingSimulation {
    public static void main(String[] args) throws InterruptedException {
        SeatInventory inventory = new SeatInventory(20, "Standard");
        int targetSeat = 5; // both counters race for the same seat

        Runnable counterA = () -> attemptBooking(inventory, targetSeat, "Counter-A");
        Runnable counterB = () -> attemptBooking(inventory, targetSeat, "Counter-B");

        Thread t1 = new Thread(counterA);
        Thread t2 = new Thread(counterB);

        t1.start();
        t2.start();
        t1.join();
        t2.join();

        System.out.println("Booking history: " + inventory.getBookingHistory());
    }

    private static void attemptBooking(SeatInventory inventory, int seatNumber, String customer) {
        try {
            inventory.bookSeat(seatNumber, customer);
            System.out.println(customer + " SUCCESS: booked seat " + seatNumber);
        } catch (SeatAlreadyBookedException e) {
            System.out.println(customer + " FAILED: " + e.getMessage());
        }
    }
}

This class instantiates two separate threads (Counter-A and Counter-B) that run concurrently and attempt to reserve seat 5 at the exact same instant, validating thread safety.

17. IN-DEPTH TECHNICAL ANALYSIS & DISCUSSION

Design-Choice Rationale: Event was modeled as an abstract class rather than an interface because ConcertEvent and SportsEvent share common concrete state (eventId, name, baseTicketPrice) as well as accessor methods. An abstract class allows this shared logic to live in one place while compelling each subclass to implement its own computeFinalPrice() override, providing a clean demonstration of inheritance and dynamic polymorphism. A HashMap<Integer, Seat> was chosen for inventory storage because seat lookups represent the hottest path in the system and HashMap provides expected O(1) time complexity. A TreeSet is used only when generating the available seats view to ensure the GUI displays them in natural sorted order.

Exception-Handling Coverage: The built-in ArrayIndexOutOfBoundsException was reused for invalid seat requests because it is an unchecked runtime exception indicating an invalid user input parameter. In contrast, SeatAlreadyBookedException was explicitly engineered as a checked exception (extending java.lang.Exception) because booking contention represents an expected business outcome that any caller must anticipate and handle. An unconditional finally block in the GUI ensures the seat grid is refreshed after every transaction attempt, preventing stale visual states.

Concurrency & Monitor Lock Behavior: With the synchronized keyword removed, two concurrent threads racing for seat 5 both read its status as AVAILABLE before either can write BOOKED back, resulting in duplicate tickets. Once synchronized is restored, the method body becomes a critical section guarded by the SeatInventory instance's intrinsic monitor lock: the second thread blocks until the first completes its write, then re-evaluates the state and safely throws SeatAlreadyBookedException.
